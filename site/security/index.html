Review boundaries

Historical deployment
V1 remains the canonical legacy Sepolia deployment.
Candidate review
V2 is frozen non-canonical candidate code. Confirm the exact commit and checksum before reviewing.
Known limitations
Review the current scope, tooling and known limitations.

Report a suspected vulnerability

Private route
Use GitHub private vulnerability reporting for sensitive findings.
Include
Affected file or contract, exact version, reproduction steps, expected behavior and impact. Use local or test-only evidence.
Keep private
Never include private keys, recovery phrases or participant data. Keep unresolved exploitable details out of public issues.
After submission
The maintainer needs to reproduce and triage the finding. Resolution requires remediation and retest evidence; submission alone does not establish a confirmed finding.
